# 使用指南与常见问题

## 把目标说清楚

最有用的输入是交付物、验收标准、材料位置和关键限制。无需预先把所有子任务或模型写出来：

```text
请使用 $adaptive-task-router:route-task 完成这个需求：
目标：……
已有材料：……
验收：……
限制：只修改指定模块，不部署。
```

插件会先检查能自行核实的信息，只询问确实会改变目标、范围或关键取舍的问题。既有路由启用不扩大业务操作授权。

## 开发与调试

```text
请使用 $adaptive-task-router:route-task 定位这个测试失败的根因，
给出最小修复，验证相关边界并解释结果。
允许有收益的并行分析，不要让两个执行者同时修改同一个文件。
```

调度应围绕真实依赖组织：只读调查可以并行，依赖接口定稿的实现应等待；验证必须针对最终稳定产物。不是所有看似分开的任务都能同时写入。

## 研究与资料分析

```text
请使用 $adaptive-task-router:route-task 比较这三份材料对同一问题的结论。
区分原始证据、推断、相互矛盾和缺失信息；最终给出可追溯的比较表。
```

可以把证据提取、反证和综合分别安排，但不能因为多个代理同意就当作事实。联网、引用和专业领域的要求仍由当前任务与领域技能决定。

## 数学建模与复杂判断

```text
请使用 $adaptive-task-router:route-task 检查这个模型：
分别核对假设、推导、边界条件、反例和实现。
重要结论需要独立复核，不用模型档位高低裁决分歧。
```

区分“局部求解困难”和“全局整合困难”。主代理更强不能保证发现所有子代理遗漏，子任务困难也不意味着全局组织必须最高档。详细矩阵以 [高档配置策略](../skills/route-task/references/high-effort-orchestration.md) 为准。

## 文档工作

```text
请使用 $adaptive-task-router:route-task 把这些材料整理成面向新维护者的说明。
先明确读者、结构和验收，再使用合适的文档技能制作交付物。
```

本插件负责分工与整合；Word、PDF、幻灯片等领域技能继续负责文件格式、渲染及专业验收。不要把安排了多个代理当成文档已经合格。

## 模型与推理限制

你可以指定可用范围、并发或某个关键任务的配置：

```text
最多同时使用两个子代理。关键证明优先考虑 Astra Max，
材料整理按需要使用 Sol 或 Luna。完成后说明实际提交的配置。
```

用户明确限制优先。指定项不受支持时，不能静默替换；自动候选不可用时，可选仍满足验收的支持配置并说明调整。模型名应以你当前工具公布的列表为准。

参考文件包含 17 项起点，但这不是必须跑完的组合，也不是自动逐档升级。Ultra 是单列的委派相关选项，不能简单视作 Max 之上的一档。

## 持续、临时例外与关闭

首次明确执行或接受启用建议后，同一对话中的新请求继续使用。以下语义必须区分：

- **“这次不用插件”**：只对指定请求及其尚未结束的范围例外。
- **“这一步不要委派”**：当前范围不创建代理，其他规则仍在。
- **“关闭插件，后续不用了”**：持续关闭，普通新请求不会重新开启。
- **“重新启用 route-task”**：显式重开。
- **“先停止”**：暂停工作，不能因启用状态尚在就自行继续。
- **“完成当前块后停止”**：只完成最小合理当前块、已有必要依赖和收尾。

恢复前应检查任务版本、文件变化、存活工作和副作用状态；有效成果继续沿用，变化的前提只重验受影响部分。

## 递归怎样避免无限扩张

Root 统一分配整树名额，分支额度包含父节点自身及预留后代。子代理不是每层都获得一份新的宿主容量。

只有专业分工、上下文隔离或独立验证有价值时才加深一层；平行任务优先作为兄弟节点，短步骤直接做。父节点必须有有用的独立工作，不能占满名额后都等待尚未创建的孩子。

记录累计创建、重试、版本和实际进展。针对同一问题连续两次无实质进展就重新诊断，换代理不会重置计数。规则详见 [协调协议](../skills/route-task/references/recursive-orchestration.md)。

## FAQ

### 为什么一次调用后不用反复勾选？

执行入口的隐式调用关闭，控制的是首次自动发现；已经明确启用后，当前对话继续沿用这套工作规则。插件不修改界面勾选，不要求宿主每轮重新读取文件。可信摘要应保留状态与限制；上下文丢失后不能保证自动恢复。

### 新对话也会自动开启吗？

没有有效继承状态的新对话不会开启。引用旧对话或文档中的“用户已同意”也不算授权。子代理只继承当前交接范围，不获得整个账号的长期授权。

### 主代理可以自动从 XHigh 切到 Max 吗？

本技能不能热切换正在运行的主代理。它优先将适合拆出的难点交给足够强的专家并核验，仍不能可靠验收才准备接续材料、提示用户切换主代理。不能把整包转交冒充主代理升级。

### 为什么简单问题没有展示分工表？

这是设计行为。持续启用不等于持续创建代理。简单请求直接完成，只有实际分派时才需要简明的配置、理由和验收说明。

### 为什么工具参数写了 Max，却仍报告“实际配置未回显”？

请求参数、创建成功和服务端实际执行配置是不同证据。若工具没有返回实际配置，就不能靠代理自述证明服务端身份。用量和耗时也只报告工具实际提供的数据。

### 会自动部署、发邮件或扩大需求吗？

路由规则不会增加外部操作权限。每个请求重新确定范围；完成目标必须的检查可以补齐，额外功能或新的外部操作只能建议，除非任务本身已经授权。

### 能否保证更省钱、更快或更准确？

没有这类保证。目标是质量达标后减少不必要的工作；多代理也会引入交接与整合成本。参考表不是基准，不能据此推算订阅扣费。

### 是后台服务或跨账号调度器吗？

不是。仓库不提供常驻服务、独立模型 API、队列系统或跨任务记忆。它使用当前 Codex 会话能用的原生能力；停止和权限控制仍依赖宿主及当前指令。
