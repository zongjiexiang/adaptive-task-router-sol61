# 原生接口与配置证据

准备实际分派时读取。以当前工具 schema、调用反馈和宿主规则为准；本文件不创造工具或权限。

## 当前接口

当前环境使用 `collaboration.spawn_agent`，及其消息、状态、等待、中断工具，均直接调用，不放入 `functions.exec`。全历史 fork 不接受模型/推理覆盖；使用 `fork_turns: "none"`，手动传必要上下文。

示例只说明参数形状，按真实任务填写上下文与名额：

```json
{
  "task_name": "catalog_evidence",
  "model": "gpt-6-luna",
  "reasoning_effort": "high",
  "fork_turns": "none",
  "message": "参与用户已在本对话明确启用的任务调度。任务：按给定规则盘点目录。输入：实际文件位置、版本及原始规则。范围：只读指定材料；不访问外部服务。交付：统计、来源及未确定项；按原始规则验收。你占用一个已分配名额，无进一步委派名额；需要拆分时报告父代理，当前先做能独立推进的工作。保留启用、停止与版本规则，不能扩大业务权限。"
}
```

每次明确 `model` 和 `reasoning_effort`。示例不强制所有子任务都是叶子；允许递归时传[协调协议](recursive-orchestration.md)及具体可分配名额。

其它原生宿主先读实际 schema，不硬塞同名参数。当前接口没有自定义角色选择参数，不凭文档虚构 `agent_type`。若其它接口选择自定义角色，其文件设置可能覆盖请求模型与档位，使用前定向核对；不要为绕过配置冲突改无关全局设置。

## 能力核对

第一次建立流程、宿主或代理配置变化、参数拒绝和能力异常时核对。通常复用任务内已核验信息；不每轮广泛联网或读取认证文件。

区分 UI 选项、工具可传参数、保存的默认设置与运行时实际配置。用户配置文件不是当前主代理运行参数的证明。必要时只读相关配置层、模型目录及官方资料，记录版本/时间，不把 API 行为套用到本地工具。

同一问题且配置、上下文仍合适时，优先原生 follow-up 复用；需要换模型、独立复核或改变研究方向时，创建携带针对性证据的新代理。不能靠提示现有代理“你现在是另一模型”更改配置，也不把新线程当成重试计数清零。

## 容量与缺失能力

容量有的包含主代理，有的只算后代；有的计算运行中，有的计算仍打开的代理。按实际定义核算，包含预留名额及整棵树中占用资源的父节点。不要仅凭“工具正在等待”推断槽位释放；仅使用宿主提供的完成、关闭或中断机制，并确认结果。

缺原生工具时单代理完成可做的授权工作；缺指定配置时区分不支持与暂时满额。满额排队或调整分工，不连续重试创建。不创建普通侧边栏任务、额外 Codex CLI 或外部 API 来替代正常分派。本插件没有 MCP 服务、后台进程或凭证。

## 证据记录

每项记录任务标识/父节点、任务与输入版本、提交的模型/档位、工具确认身份、状态、证据、验证和调整理由。复杂任务才维护完整记录，简单任务不填长表。

成功创建且提交了某组参数，可以证明该调用被接受；底层实际模型/档位只有宿主回显才能确认。代理自述不算证明，未回显标记未回显。只报告工具提供的耗时与用量，不从账户额度差额反推单任务成本或订阅扣费。

参考：[官方子代理配置](https://learn.chatgpt.com/docs/agent-configuration/subagents)。技能名额和只读要求是指令约束；宿主权限、真实模型与容量由运行时执行。
