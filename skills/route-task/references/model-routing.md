# 模型与推理等级起始策略

Sol 系列仅使用 `gpt-6.1-sol`，不使用其他 Sol 型号或将其作为回退。Astra/Luna 的动态选型能力保留；主线程配置仍由用户和宿主决定。

用途：为已明确的子任务选择够用的模型和推理投入。复杂高档组合同时参考[高档配置](high-effort-orchestration.md)。本表综合用户提供的选型对话与官方模型定位，是工作策略，不是逐档实测结论。不能据此声称固定成功率、耗时、费用倍率或跨模型能力等价。

## 先看难在哪里

- 明确规则、可靠原文、固定接口和可执行验收：优先考虑 Luna；真正机械的批处理优先确定性工具。
- 多步骤实现、调试、框架行为和多约束权衡：优先考虑 Sol。
- 隐含约束、核心科学判断、重要全局设计、难以识别的错误：考虑 Astra，并按难度直接给足推理投入。
- “已知道应当如何做，但实现复杂”可以提高当前模型推理；“尚不知道哪种方法成立”常需要更强模型。
- 任务重要不等于全部步骤都用 Max；任务长也不等于推理困难。普通查询不应为展示混合模型而拆成多个代理。

## 15 种基础组合

| 模型 ID | 推理等级 | 值得优先尝试的任务 | 调整信号 |
| --- | --- | --- | --- |
| `gpt-6-luna` | `low` | 固定规则字段提取、短分类、格式转换 | 出现规则歧义或异常分支，重新评估 |
| `gpt-6-luna` | `medium` | 轻量多步整理、明确模板、小脚本 | 出现隐藏约束或跨文件依赖，考虑 Sol |
| `gpt-6-luna` | `high` | 明确规格的常规执行、证据定位、常规测试与结构化摘要 | 根因或结论需要复杂判断，交给 Sol/Astra |
| `gpt-6-luna` | `xhigh` | 局部分支复杂的修改、边界测试、独立模块修复 | 方法本身尚未确定，优先提高模型能力 |
| `gpt-6-luna` | `max` | 目标固定、测试充分的困难局部实现 | 无进展或暴露全局问题时换模型，不无限重试 |
| `gpt-6.1-sol` | `low` | 上下文明确的短技术任务、小范围修改 | 需要读完整项目并设计验证，不继续按短任务处理 |
| `gpt-6.1-sol` | `medium` | 常规功能、接口接入、调试、分析和文档 | 较多耦合、重要取舍或难查错误，提升配置 |
| `gpt-6.1-sol` | `high` | 复杂实现、多文件开发、数值算法实现、非平凡调试 | 跨模块复杂性突出时考虑 XHigh；科学判断另行检查 |
| `gpt-6.1-sol` | `xhigh` | 跨模块诊断、较大重构、多约束工程 | 暴露模型定义或机制冲突时考虑 Astra |
| `gpt-6.1-sol` | `max` | 已明确的困难技术瓶颈、严密算法细节 | 判断能力不足时提高模型，不能假定 Max 必胜 XHigh |
| `gpt-6-astra` | `low` | 复杂上下文中的短判断、方案初筛、识别歧义 | 推导链长或错误代价高时提高投入 |
| `gpt-6-astra` | `medium` | 多来源综合、方案评估、跨模块设计讨论 | 核心机制或深层逻辑争议转 High/XHigh |
| `gpt-6-astra` | `high` | 重要设计、研究分析、非平凡数学、复杂根因与关键审查 | 全局科学架构或深层冲突考虑 XHigh |
| `gpt-6-astra` | `xhigh` | 核心建模、关键假设检验、全局架构与实质审查 | 局部或全局仍有深推理瓶颈时考虑 Max |
| `gpt-6-astra` | `max` | 关键证明、机制争议、困难的全局整合与验证 | 避免连带承担机械执行；无依据的新尝试应停止 |

常见起点：明确执行用 Luna High，普通技术工作用 Sol Medium，复杂实现用 Sol High，跨模块工程用 Sol XHigh，重要判断用 Astra High，核心建模与全局审查用 Astra XHigh。Low/Medium/Max 都有用途，不能机械地排除或固定为统一默认值。

## 另外 2 种运行模式

| 模型 ID | 模式 | 适用情况与限制 |
| --- | --- | --- |
| `gpt-6.1-sol` | `ultra` | 已明确接口和验收的大任务并行统筹；前提是宿主支持且授权委派，不能让多个代理争用核心文件 |
| `gpt-6-astra` | `ultra` | 复杂工程或研究中多条独立工作线的统筹；主代理仍须处理证据冲突和全局一致性 |

Ultra 是宿主提供的运行选项，其委派行为受当前产品与会话规则约束，不能当成在 Max 之上再增加一级独立单模型能力。实际基础推理映射依赖客户端与模型目录。2026-09-23 本机缓存曾对 Astra 声明 `multi_agent_reasoning_effort: xhigh`；这是带日期的元数据观察，不是未来配置或每次请求的证明。

Luna 不选择 Ultra。明确要求子代理的工作不必先切 Ultra；本插件已经提供按需委派指令。子代理通常在 Low 至 Max 中按需选型；进一步分派取决于工具、任务收益和已分配名额，不依赖切换 Ultra。在共享容量内允许有收益的递归，详见[协调协议](recursive-orchestration.md)。用户已选择 Ultra 时遵守该设置和实际工具能力，不擅改主代理。

## 当前能力与资料冲突

1. 实际调用以当前工具公布的模型、档位和成功/拒绝反馈为准。
2. 必要时只读检查本机模型目录，并记录缓存时间；不要读取认证文件来发现模型。
3. 需要联网确认时查官方资料；“没有搜到”不能推出模型尚未提供，文档默认值也不等于当前账户配置。
4. 不提供未经验证的固定扣费、时延或“Luna Max 等于 Sol 某档”的换算。Fast/服务等级与推理是独立配置，不为选型擅自开启。
