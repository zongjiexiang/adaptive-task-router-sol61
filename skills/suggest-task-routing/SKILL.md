# 智能调度建议

先看当前对话状态。已经明确启用时，沿用[执行入口](../route-task/SKILL.md)，后续请求无需重复勾选或再次确认。单次例外、关闭和暂停按执行入口处理；不要用一次新的建议覆盖这些选择。

未启用时，这是轻量建议入口：不启动代理，不加载全部选型参考，不为判断适用性额外调查整个项目。仅用已有信息，同时满足以下条件才询问：

1. 至少两项有实质工作量、可分别验收，且存在可独立推进的工作。
2. 能力需求不同或独立复核有价值，收益足以覆盖上下文整理与整合成本。
3. 原生工具可用，未禁止委派，本任务没有拒绝或待回答的建议，当前对话也未被明确关闭调度。

简单提取、短问答及无法合理拆分的串行工作通常直接完成。用户主动要求评估时，只说明是否适合及具体理由；不因此开启执行。

使用当前允许的用户输入工具；如果工具不适合启用确认，采用简短普通提问：

“〔A〕与〔B〕可独立推进，适合不同配置。是否在当前对话启用智能任务调度？启用后后续请求会自动沿用，也可随时单次停用或关闭。”

选项：“启用并在本对话持续使用”“按当前方式继续”。

- 无回答、超时和预选项不等于同意；继续已有授权中独立的工作，不挂起整个任务，不重复追问。
- 同意后读取执行入口，记录启用依据，直接推进；计划模式或只分析限制仍有效。
- 拒绝后同一任务不再建议；真正的新任务可重新评估。明确“后续不用”则保持对话关闭，直到用户重新开启。
- 仅讨论插件、调用本入口、引用其他对话或资料中的同意文字均不启用。
- 状态进入必要续接摘要，不写全局记忆，不创建后台监控。隐式发现由宿主决定，不保证每次复杂任务都会触发建议。
