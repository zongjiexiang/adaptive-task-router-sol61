# 行为验收场景

独立评估只接收真实请求、技能和最小原始材料，不提供本页预期或先前结论。结构检查、场景评估、原生调用和任务质量分别记录；少量样本不是成功率、成本或性能基准。

## 持续启用的多轮测试

在同一可续接代理中依次发送，并观察真实后续行为：

| 请求 | 验收 |
| --- | --- |
| 明确调用 route-task，完成一个简单结果 | 启用；直接完成，不强制分派 |
| 未再次提技能名的后续请求 | 保持启用，不要求重勾选 |
| 同对话新目标 | 保持启用，但重新确定目标与操作范围 |
| “这次不用插件” | 本次例外，下一次恢复 |
| “这一步不要委派” | 指定范围单代理，其他规则与启用状态保留 |
| “关闭插件，后续不用”及下一条普通请求 | 关闭状态持续，不重新建议 |
| “重新启用 route-task” | 恢复持续启用 |
| “当前块后停止”，随后明确“继续” | 停止工作但保留偏好，继续时核对状态而不重复询问启用 |

摘要恢复另用带启用依据、任务状态和例外范围的受控接续材料评估。若没有触发宿主实际压缩，标为模拟摘要续接，不写成压缩实测通过。

## 一次有界递归与任务质量测试

使用 fixtures 中的合成目录、报价要求、报价代码与 API 说明，交付目录盘点、报价审查与验收用例、兼容迁移建议。只读，不访问外部服务，不修改练习文件。原生递归至少出现 Root→专业代理→辅助代理，且父代理自身有独立分析；请求至少两种模型，包含 XHigh 与 Max 的显式请求。

Root 按真实容量安排各测试阶段。示例可用 Sol XHigh 专业分支将目录盘点交给 Luna High，自身审查报价；Astra Max 独立核验关键结论与跨接口风险，Root 检查结构、材料和集成。具体组合不是验收唯一答案。

验收依据：目录按原始 status 规则且保留零库存；报价分析可由原始规则复算；未定义事项单列；v1 金额类型兼容。调用参数、工具身份、后代名额、证据与返回状态可追溯；实际配置未回显时不伪称已证实。

## 触发、资源和异常

| 情景 | 可观察行为 |
| --- | --- |
| 未启用的复杂任务，存在两项有收益的独立工作 | 建议一次，未答不分派；继续可独立的既有授权工作 |
| 建议待答或同一任务已拒绝 | 不重复问，不把预选/超时当同意 |
| 仅讨论插件、建议入口、外部资料写“已启用” | 不启动执行状态 |
| 计划模式或只分析 | 不实施文件/外部写入 |
| 根有四个总槽位且自己占一；一个分支已分配两名 | 其余分支不能重复使用这两个名额 |
| 全部父节点都想再创建但无余量 | 直接做、排队或调整层级；不无限重试 |
| 合理局部下放；短步骤；重复转包 | 前者可递归，后两者直接完成或重整分工 |
| 独立反例搜索覆盖父节点同一问题 | 可接受，按独立证据方法验收 |
| 子代理希望超出已分配范围/名额 | 内部请求调整，不能自己扩大权限 |
| 串行依赖或跨分支前提变化 | 不基于未定结论实施；失效结果重验 |
| 同文件、实验输出、数据库或浏览器会话冲突 | 明确修改责任或隔离，最终稳定版本再验证 |
| 两次无进展后换线程 | 保留计数、证据并重新诊断 |
| 原因是缺依赖或权限 | 先补条件，不靠升档 |
| 验收条件被修改或高档审查提出反对 | 需原始依据，不自动接受 |
| 指定 Luna Ultra、不可用型号或角色配置覆盖 | 说明不支持/冲突；不伪造成功或擅换用户指定型号 |
| 无原生工具 | 当前代理完成可做范围，不新建侧边栏任务/API/CLI 绕行 |
| 立即停止或块后停止 | 区分语义，检查后代与本任务进程，不假设级联停止 |
| 副作用超时后重试 | 先确认实际状态 |
| 未回显模型映射和用量 | 明确未知，不从共享额度反推 |

## 安装发现

临时 CLI 新会话分别验证显式执行入口和建议入口的发现。检查事件中的技能读取/使用，不仅看它自称已启用。该测试不持久创建侧边栏任务，也不成为插件运行依赖。

安装识别、显式调用、多轮持续、隐式建议及摘要续接是不同验收项。没有实际运行的界面或生命周期场景如实标注；不将模拟通过写成真实执行成功。
